# MangaAlpha v3.2.2

本版本聚焦 `v3.2` 多源元数据与 NSFW 封面体验修复：新增 Bangumi NSFW 封面从就绪离线图库的只读保底加载、精准迁移升级前的历史 Bangumi 自动绑定、修复 `gallery_v1` 括号标题匹配与多版本消歧、统一书库刮削入口，并补齐源同步体验与脱敏诊断日志。

## 主要更新与修复

### 1. Bangumi NSFW 封面离线图库只读保底
- **无缝保底加载**：当已绑定 Bangumi 的 NSFW 作品在封面模式为 `auto` 或 `bangumi`（仅 `book` 模式跳过外部封面）且当前用户允许并开启 NSFW 展示时，若 Bangumi 官方封面因账号未登录或权限受限返回不可用（401 / 403 / 404 等），服务端将自动按只读方式从已就绪的外部离线图库源（优先当前书库顺延链，再兜底全局已启用且就绪的 `offline_sqlite` 源）按高置信标题与作者匹配加载并缓存封面。
- **零侵入与按用户隔离熔断**：保底封面完全只读，不修改 `series_metadata` 中的 Bangumi 绑定及字段；按用户维度记录连续 Bangumi NSFW 封面不可用次数（连续 2 次后对该用户进入 30 分钟熔断短路，直接走离线图库保底），并在用户重新授权/刷新 Bangumi Token 或管理员清理封面缓存时自动重置。

### 2. 历史绑定精准迁移与 `gallery_v1` 括号标题匹配修复
- **历史自动绑定精准回填**：启动迁移自动检查升级 `v3.2` 前 `match_origin` 为空的旧 Bangumi 绑定——依据历史 `scrape_confidence`（手动与 AI Agent 绑定恒为 `1.0`，自动刮削上限 `0.99`）及 17 个字段锁，将历史手动/Agent 绑定与已锁字段精准回填为 `manual`（持续保护不被覆盖），将历史自动刮削记录回填为 `auto`，使「全量强制重刮 (`force`)」在调整多源顺延链后能够正常重刷旧作品。
- **`gallery_v1` 括号标题实时打分与多版本消歧**：无需重下离线包或重建 Sidecar 索引，查询阶段对 FTS5 召回候选批量读取上游中/日文标题与画廊状态，自动剥离展会/社团/作者/汉化括号噪音后比对核心书名并结合显式作者信息加权（作者冲突自动压分防误绑）；同一作品存在多版本（如原版、汉化、修订、已删画廊）时优先选择有效版本，避免被歧义阈值误拒。

### 3. 书库刮削入口统一、源同步体验优化与界面降噪
- **书库管理「刮削」按钮统一**：书库管理卡片（普通库与联合库）按钮由 `刮削 Bangumi` 更名为 `刮削`，点击改为触发统一多源刮削接口（`POST /admin/api/metadata/scrape`，`mode=retry_unmatched`），按各库顺延链重试未匹配与新作品；同步清理流水线阶段、定时配置、批量补封面、系统设置及油猴脚本配对页等处的旧版 `Bangumi 刮削` 残余文案。
- **首次下载自动启用 & 顺延链停用警示**：首次手动下载未就绪的新外部数据源成功后自动开启 `enabled`（已就绪源的更新检查及已手动停用后改地址重建的源均保留原开关状态）；书库顺延链卡片与编辑弹窗对已停用源显眼标注 `已停用（不生效）` 徽标。
- **在线 API 界面降噪**：保留后端通用 `GET ?q=` 在线补全扩展协议不破坏兼容；在无任何同时满足「已启用 + 开启在线补全 + 已填在线 API」的 `offline_sqlite` 源时自动隐藏「允许低速在线补全」勾选框，并将数据源配置弹窗中的「在线 API 补全地址」收拢至可折叠「高级选项（可选：自定义在线 API）」区域。
- **诊断日志补齐**：新增脱敏的 `extmeta_scrape` 批量刮削汇总事件与 `extmeta_cover` verbose 封面失败诊断事件，排障清晰可观测且不泄露任何书名、路径或原始 URL。

## 升级说明

- **平滑原地升级**：服务端、Docker 与 Android 正式包（`versionCode=3020299`）均可直接从 `v3.2.1` 或更早版本原地覆盖升级。
- 首次启动会自动执行轻量、幂等的 `match_origin` 历史数据回填迁移，无需重下离线数据库，也无需重建 Sidecar 索引。
